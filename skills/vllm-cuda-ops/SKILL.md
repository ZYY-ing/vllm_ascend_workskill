# CUDA vLLM 编译与服务

核对目标服务器、GPU、源码分支、基础镜像、权重和用户授权范围；已有编译/服务先查 PID、日志及退出码，不重复执行。

完整命令与参数含义见 [H200源码编译与服务](references/h200-source-build.md)。只读需要的阶段：基础条件、容器和源码副本、依赖、编译、JIT排障、镜像保存、服务与curl。该文档的 HY4/NCCL/FlashInfer 组合是已核实案例，不作为其他分支的固定版本要求。

## 关键判断

- 基础镜像的旧 vLLM 不代表目标源码已安装；确认虚拟环境、实际 `vllm.__file__`、原生扩展和模型注册。PYTHONPATH不能代替编译。
- 保留宿主机原始源码，在容器可写副本中编译。升级或卸载前确认是自己的目标环境，避免对运行中的服务重编译。
- 对齐 Python/Torch/CUDA/扩展 ABI；源码变更涉及原生扩展时重编译，Python修改需要重启进程才会生效。
- CUDA 缺头文件/库时检查真实安装路径，只补需要的库文件；不混用另一套 CRT、不关闭 FlashInfer 版本校验。
- 参数保留用户指定值，量化以权重与后端支持为准。MTP、长上下文、图模式和客户端并发均需实测，不能由 CPU 导入推断成功。

## 验收与边界

停止或启动前核对 GPU/端口占用及所属容器，只处理获授权服务；不改宿主驱动、不全局杀进程。记录镜像 ID、代码来源、依赖、构建日志/退出码、实际启动命令和 curl 响应；凭据、认证URL及私有输出不进仓库。

依次验收编译退出0、扩展导入、源码位置、health/models及最终答案和usage；仅HTTP200或进度100%不等于模型回答完成。长JIT根据编译活动与日志判断，不凭单条等待警告重启。

权重下载与完整校验可使用 `weight-download`；GPQA、Hallusion等评测与思考标记提取属于 `model-evaluation`。没有这些技能时按用户提供的等价工具完成，不为部署强制安装其他技能。
